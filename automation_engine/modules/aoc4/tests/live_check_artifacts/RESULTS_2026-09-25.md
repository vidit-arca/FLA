## 4. Findings & limitations

1. **Calibration is high, net score impact is negative on these 2 sheets.** The judge only
   overrides 6% of flags, but its favourite override (`COMP_MSME`) was wrong in both scored
   companies → 81.3% → 77.1%.
2. **MSME override root cause:** the model treats *any* MSME mention (trade-payables ageing
   schedule, boilerplate "dues have been determined…" note) as applicability evidence, while
   the reviewer marks MSME "Not Applicable" unless actual dues are established. Conversely on
   OXAIR (real ₹21.7 L dues) the same override looks *correct* — rule intent needs pinning
   down in the judge prompt (needs-listing vs. default-in-payment semantics).
3. **Insap `COMP_DEPOSIT_DEC` — model self-contradiction:** verdict "Not Applicable" while its
   own reason says the director's loan "triggers the requirement". One-token flip from a fix.
4. **Two Insap errors are upstream facts, not judge scope:** false `is_subsidiary_or_holding`
   (text mention of "subsidiary company") makes the engine say "not a small company", which
   cascades to CARO. Deterministic-gated, LLM cannot touch these rows.
5. **Charge-form (Insap) is evidence-unavailable:** ground truth "Applicable" comes from the
   MCA registry (CHG-4 SRN), not the annual report. Document-only judging cannot fix it.
6. **AOC-2 / RPT-omnibus (Insap) is a GT-semantics split:** the AR itself states "AOC-2 is not
   applicable"; the reviewer still marks Applicable (fill §188 sheet). The model trusted the
   document. Decide whether reviewer or document should win, then encode it in the prompt.
7. **Ben 2 stays `unknown`:** gated on missing shareholders/registrar data; model answered
   "Cannot determine" too. Sheet marks it Not Applicable (unlisted) — rule could short-circuit
   on listing status instead of missing data.
8. **Robustness:** 0 HTTP errors across 108 live calls; every failure path (undecided,
   timeout, server error) fell back to deterministic exactly as designed; 116 unit tests green.
